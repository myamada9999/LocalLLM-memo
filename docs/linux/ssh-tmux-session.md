# SSHとtmux：再接続・スクロール・複数端末・貼り付け

tmuxをSSH接続先で起動すると、その中のシェルや処理を保ったままSSHを切断し、あとから同じ端末に戻れる。モデルのダウンロードや推論サーバーの起動など、長時間の作業に便利。

## 1. tmuxをインストールする（Debian / Ubuntu）

SSH接続先で実行する。

```bash
sudo apt update
sudo apt install tmux
```

## 2. SSH接続して名前付きセッションを作る

接続元の端末で実行する。ユーザー名とホスト名は自分の環境に置き換える。

```bash
ssh USER@HOST
```

接続先でtmuxを起動する。

```bash
tmux new -s work
```

以降の作業やコマンドは、このtmux内で実行する。tmuxを起動する前から通常のSSH端末で動いていた処理が、自動でtmuxへ移るわけではない。

## 3. 処理を続けたまま端末から離れる

**Ctrl+bを押し、キーを離してからdを押す。**

この操作をデタッチと呼ぶ。通常のSSH端末に戻り、tmux内の処理は接続先で動き続ける。

通常のSSH端末に戻ったら、次のコマンドでSSHを切断できる。

```bash
exit
```

## 4. あとから接続し直す

接続元で再びSSH接続する。

```bash
ssh USER@HOST
```

接続先でセッション一覧を確認し、同じセッションへ戻る。

```bash
tmux ls
tmux attach -t work
```

元の端末表示と、その中で動いている処理に戻れる。切断中に処理が終了していた場合は、通常はその後のシェルと端末上に残った出力を確認できる。

既存のworkセッションがあれば接続し、なければ作成するには：

```bash
tmux new -A -s work
```

## よく使う操作

| 操作 | コマンド / キー |
| --- | --- |
| 新しいセッションを作る | `tmux new -s work` |
| 一時的に離れる | Ctrl+b → d |
| セッション一覧を見る | `tmux ls` |
| 同じセッションに戻る | `tmux attach -t work` |
| 古いクライアント接続を外して戻る | `tmux attach -d -t work` |
| 既存セッションへ接続、なければ作成 | `tmux new -A -s work` |

`attach -d`は、他の端末からの接続をデタッチする。複数の端末で意図的に同じセッションを共有している場合は、通常の`attach`を使う。

## スクロール・ウィンドウ・ペインの基本操作

以下は既定のキーバインド。設定で変更している場合は、その設定に従う。**「Ctrl+b → キー」は、Ctrl+bを押して離し、その後にキーを押す。**

### 過去の出力をスクロールする

| やりたいこと | 操作 |
| --- | --- |
| コピーモードに入る | Ctrl+b → `[` |
| 上下にスクロール | ↑ / ↓ |
| ページ単位でスクロール | PageUp / PageDown |
| コピーモードを抜け、通常の入力に戻る | `q`（既定のemacsモード）／Escape（viモード） |

コピーモード中は、キー操作がスクロールや選択に使われる。コマンドを入力する前にモードを抜ける。残っているスクロール履歴の範囲まで遡れる。

### 端末を増やして切り替える（ウィンドウ）

ウィンドウはタブのように切り替えて使える。同じtmuxセッション内で複数の端末を持てる。

| やりたいこと | 操作 |
| --- | --- |
| 新しいウィンドウを作る | Ctrl+b → `c` |
| 次のウィンドウへ切り替える | Ctrl+b → `n` |
| 前のウィンドウへ切り替える | Ctrl+b → `p` |
| 一覧から選ぶ | Ctrl+b → `w` |
| 番号で直接切り替える | Ctrl+b → `0`～`9` |
| ウィンドウ名を変更する | Ctrl+b → `,` |

例えば、0番でLLMサーバーを動かし、1番でGPUを確認、2番で別の作業ができる。GPU監視用ウィンドウでは次のように実行する。

```bash
watch -n 1 nvidia-smi
```

ウィンドウを切り替えても、それぞれの処理は継続する。

### 同じ画面に端末を並べる（ペイン）

| やりたいこと | 操作 |
| --- | --- |
| 左右に分割する | Ctrl+b → `%` |
| 上下に分割する | Ctrl+b → `"` |
| ペイン間を移動する | Ctrl+b → 矢印キー |
| 選択中のペインを最大化／元に戻す | Ctrl+b → `z` |

`%`や`"`は、その文字を入力するために必要なShiftなどと一緒に押す。

## マウスでスクロール・端末切り替えをする

tmux内のシェルで実行すると、現在のtmuxサーバーでマウス操作が有効になる。

```bash
tmux set -g mouse on
```

ホイールで履歴をスクロールし、ステータスバーのウィンドウ名や各ペインをクリックして切り替えられる。

次回以降も有効にするには、**SSH接続先の**`~/.tmux.conf`に次の行を追加する。既存の設定ファイルは上書きせず、同じ設定があれば編集する。

```conf
set -g mouse on
```

設定ファイルを変更して、現在のtmuxにも反映するには：

```bash
tmux source-file ~/.tmux.conf
```

## 貼り付け（paste）

コピー元によって、貼り付け方法が異なる。

| コピー元 | 貼り付け方法 |
| --- | --- |
| ブラウザや別のアプリなど、接続元PCのクリップボード | 接続元のLinux端末でCtrl+Shift+V（端末アプリの設定による） |
| tmuxのコピーモードでコピーしたテキスト（tmuxのバッファ） | Ctrl+b → `]` |

SSH接続中でも、接続元の端末でCtrl+Shift+Vを押せば、手元のクリップボードの内容をtmux内の端末へ送れる。tmuxのコピーモードを抜けてから貼り付ける。Ctrl+Vだけでは通常、端末への貼り付けにならない。

端末の右クリックメニューにある「貼り付け」も使える。`mouse on`で右クリックがtmuxに取られる場合は、**Shiftを押しながら右クリック**を試す。マウス操作を一時的に端末側へ渡す方法は、端末アプリによって異なる。

接続元PCのクリップボードとtmuxのバッファは、別のもの。連携設定がない場合、ブラウザでコピーしただけではCtrl+b → `]`で貼り付けられない。

## 注意点

- tmux内で`exit`を実行すると、そのペインのシェルが終了する。最後のペインが閉じるとセッションも終了する。一時的に離れるときはCtrl+b → dを使う。
- SSHが突然切れても、通常はtmuxセッションとその中の処理は残る。ただし、接続先のログアウト時にユーザーの全プロセスを終了する設定などがある場合は、その設定に左右される。
- 接続元PCの端末を閉じても、接続先が動いていれば作業を継続できる。接続先PCの再起動・電源オフ・スリープでは継続できない（スリープ中は処理が停止する）。
- tmuxは端末を維持する仕組みで、処理の自動再起動や完全なログ保存は別途必要。常時稼働させる推論サーバーを自動起動・監視する用途にはsystemdなどを検討する。
- `tmux ls`でセッションが見つからない場合は、同じ接続先・同じユーザーでログインしているかを確認する。
